
### 12.7 工具固化（可复现入口，随本轮入库）

本节所有数字都由下面三个脚本产出，不再依赖被 `.gitignore` 忽略的临时探针（`tools/_*`）：

| 工具 | 用途 | 关键输出 |
|---|---|---|
| `tools/bench_assemble.py` | 装配 vs run 拆分（`perf_counter` 累计口径） | `assemble_p50_ms` / `asm_share_pct` / `load_for_ms`；`--profile` 出逐函数表 |
| `tools/bench_parallel.py` | 并行吞吐**归一化**基准 | `core_fps`（CPU 口径单核）/ `cores_eff`（实际核数）/ `pool_eff`（归一化效率） |
| `tools/check_loadfor.py` | `load_for` 等价性校验 | 505 stem × 3 写法 + 真实阵容 + 边界输入，判据 `TOTAL FAILS = 0` |

**用法与判读**：

```bash
python -X utf8 tools/bench_assemble.py --n 12 --rounds 7 --profile
python -X utf8 tools/bench_parallel.py --n 32 --aff 0,2,4,6 --aff 4,5,6,7
python -X utf8 tools/check_loadfor.py    # 改 gd_to_py.py 的档二逻辑后必跑
```

> ⚠️ `bench_parallel.py` 里 `pool_eff` 是唯一跨时段可比的指标：`tput`（场/s）会随外部负载
> 上下浮动一倍，`cores_eff` 把这件事显式量出来，`pool_eff = tput / (core_fps × workers)` 才是并行本身的质量。
> `--n` 不要低于 32——4 worker 各跑 4 场时，池启动成本还没摊完，`pool_eff` 会被系统性低估。
