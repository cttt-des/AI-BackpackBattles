#### G 类：高风险高收益——**受控试错**（不在"不敢碰"之列）

> **方法论**（2026-11-14，用户提出、我认可）：有风险≠不做。
> 正确的顺序是：**先 commit+push 备份 → 再动手 → 语义偏移先尽力修 → 实在修不了才回退**。
> 本项目恰好具备这个前提：**语义偏移是可检测的**（1690 逐行 + 三闸 + `match` 分布回读）。
> 只要「检测-修复-回退」这条链是通的，试错的期望值就是正的。

**受控试错协议（每一项都必须走完，写死在 §4.6）**：

| 步 | 动作 | 判据 |
|---|---|---|
| 0 | `git commit` + **`git push origin master`**（备份必须到远端，本地提交不算） | 远端可查 |
| 1 | 在**独立分支或独立 worktree** 上动手（不污染主树） | `git status` 干净可分 |
| 2 | 实现 | — |
| 3 | **偏移检测**：seed 双态 → REG9 → 60 场 → 1690（`match` 分布） | 全绿才算语义一致 |
| 4 | **偏移则修**：优先修实现（不是修判据）；每修一次重跑 3 | 时间盒见 §4.6 |
| 5 | 修不动 → `git checkout` 回主树，结论写「试过 + 失败位置 + 卡在哪」 | — |
| 6 | 成功 → 合入主树，附收益实测（`mean_ms` 交错 A/B） | ≥2% 或零风险降复杂度 |

**为什么 G1/G2 仍然排在 A–F 之后**（不是因为"不敢"，是因为**顺序依赖**）：

1. **A1 是它们的上游**：事件系统 20.6% 是纯 Python 层（`logEvent` 每事件 28µs），
   任何重写都得先把它做完——否则重写完仍要跨语言回调 Python 记事件。
2. **B 类给了 G 类"标尺"**：trigger 链 45.2% 内部构成（`emitAndLog` 占 58%、`call_funcv` 等）测清楚后，
   才知道 C++ 重写要替代的是哪一段、值多少。**没有这个标尺，G2 的收益只能靠猜**。
3. **G2 的收益来源已被本轮证伪一半**：编译态只剩 6.1 帧/tick，
   「消除函数调用边界」不成立 ⇒ 必须先重新论证，否则是拿 XL 成本赌一个未知数。

**关于「已判否」的措辞修正（重要）**：

> §2.2 里「换语言 C++/Rust ❌ 已有证据关闭」应改为「**❌ 部分证伪**」：
> 被证伪的是「属性访问/slot 类型化」（1.07–1.10x），**未被证伪的是「整场实现替换」**。
> 这是 §1 纪律「判否前先确认判据测的是不是同一件事」的原话对照——上一轮的关闭记录本身违反了这条纪律。
> 本轮已把该项移入 G2，附「必须先论证收益来源」的启动条件。
