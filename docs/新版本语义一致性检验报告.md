## 1 作者这一版改了什么

对比上一版（11-13 打包）与新版（11-14 16:55），**只有 3 个文件变化**：

| 文件 | 变化 | 影响 |
|---|---|---|
| `native_sim/sim.py` | `charge_frame` 从「固定 (0,0)」改为「按 rotation 查 runtime 的 rot 表」；支持 `rot` 键 | **修了一个真 bug**（见 §2） |
| `native_sim/engine_wrapper.cpp` | 新增调试导出 `gd_sim_set_dbg_events` / `gd_sim_dbg_event_count` / `gd_sim_dbg_event_line`（线程局部存储） | 可观测性提升，**无语义影响** |

`gd_rt.cpp`、`gd_rt.hpp`、`__init__.py`、`README.md` **完全未变**。

### 1.1 一个必须说明的包装问题

新版**只带 `libgdcore.dylib`（macOS），没有 Windows 的 dll**，且 `sim.py` 里
`_DEFAULT_LIB_PATH` 硬编码为 `.dylib`。Windows 上直接跑会报
`OSError: [WinError 193] 不是有效的 Win32 应用程序`。

**本次检验的处理**：

```python
_DEFAULT_LIB_PATH = _ROOT / ("libgdcore.dll" if sys.platform == "win32" else "libgdcore.dylib")
```

然后用 MinGW 自行编译（`build_windows.py` 是我方补的，不在作者包里）。**建议作者下次包里带上 Windows dll。**

## 2 作者修的那个 bug 是真的

用 `cases dict`（而非夹具 lineup）直接喂 `pack_side` 时：

| | 旧版 | 新版 |
|---|---|---|
| `charge_frame` 取值 | **全部 `(0,0)`** | 按 rotation 正确查表 |

实测 280 个物品实例里 **247 个（88%）取值不同**：

```
Leather Bag       old=(0,0)  new=(-1,-1)
Battery           old=(0,0)  new=(1,1)
Potion Belt       old=(0,0)  new=(0,-2)
Fanny Pack        old=(0,0)  new=(1,-1)
```

这是**电荷格映射原点**（`getGlobalPointsForCells` 的旋转系原点）。旧版取 `(0,0)` 意味着
电荷类物品（Battery / Coil / Resistor / Tesla Coil 等）在非 0° 朝向下映射错了格子。

### 2.1 但它不影响当前对齐口径

走**夹具 lineup** 路径时（`oracle_*.json`），187 个实例的 `charge_frame` **完全一致**——
因为夹具条目自带 `charge_frame` 字段，`pack_side` 直接取了，没走 fallback 分支。

⇒ **这个修复是「让 cases dict 直传路径正确」，对齐测试走夹具，所以看不到差异。**
**这是真修复，只是不在我们的对齐路径上。**

### 4.1 这 24 场的性质（延续上一轮结论）

上一轮已对 30 场做过定性：**7 场是「同一 tick 发出不同事件」**。
全量的 24 场里，30 场样本中的 12 场全部重现，其余 12 场是新出现的（因为全量覆盖面更广）。

## 5 判定

### 5.1 语义一致性：**通过**

| 检验项 | 结果 |
|---|---|
| 与上一版的事件流等价性 | ✅ **30/30 逐场一致** |
| 新增回归 | ✅ **无**（0 场变化） |
| 全量对齐 | ✅ **98.58%（1666/1690）** |
| winner 一致 | ✅ **99.94%（1689/1690）** |
| 运行异常 | ✅ **0** |

**作者这一版的改动是安全的**：它修了一个真 bug（charge_frame），加了有用的调试导出，
没有改变任何已有行为。

### 5.2 但核心缺口**没有修**

作者这一版**仍然没有承接** `activation_order` / `rng_state` / `gem_lens` 三项。
这意味着：

> **任何用 C++ 版做对齐验证的人，都必须自己打补丁**，否则会得到 0/30（像我们第一轮那样），
> 或者得出「C++ 版有 30 场分歧」这种错误结论。

**这三项是「要不要做对齐」的前提，不是可选项。** 建议作者优先补上。
