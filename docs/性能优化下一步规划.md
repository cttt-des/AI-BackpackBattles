## B 已判否（不要再试，除非触发条件成立）

### B-1 语义红线（永久不可修）

| 项 | 为什么 |
|---|---|
| `character()` 内联 | Gem 覆写，虚派发必须保留 |
| 事件驱动调度（只 tick 到期物品） | 改帧内调用集合 = 换内核 |
| 双侧循环合并 / 跳过死方 tick | 改帧内求值次序 |
| `f32` 换 float64 / 降 tick 频率 | 直接破确定性 |
| Godot 无头当产品运行时 | GDScript VM 更慢、打包更重 |

## C 仍开放：算法层（当前唯一有实证空间的方向）

### C-1 为什么是「调用次数」而不是「单次成本」

`profile_v14_purepy.json`（n=3，top30 共 **116 万**调用）：

| 调用 | 3 场合计 | 冗余点 |
|---|---|---|
| `CoreItem.character()` | **245,820** | 虚派发；`getSpeed`/`getStackSpeedMods` 每次各调 1–2 次 |
| `_rt.f32` | 138,806 | float32 垫片，已做整数值快路径 |
| `getCold` / `getHeat` | 各 **71,986** | `getStackSpeedMods` 一次调两个 |
| `CoreItem.getSpeed` | 71,986 | tick 内每物品至少一次 |
| `CoreBuff._tick` | 54,032 | — |
| `_rt._iter` | 51,190 | C1 已消 91.4%，残量是 float/dict 形态 |
| `PCG32.next_u32` | 45,322 | — |
| `isItemAffected` | 32,448 | 影响格判定 |
| `EnumDict.__getattr__` | 29,854 | 枚举点号访问漏网 |
| `isBag` / `_hasBehaviorMethod` | 各 2.8 万 | 行为派发判定 |
| `Vector2.__hash__` | 24,006 | 格集 set 操作 |

**推论**：L1-Q 证明「压低单次成本」已榨干（槽位化只省数十 ns/调用）；
但 `getSpeed` 一次调用会连带 2 次 `getHeat/getCold` + 1–2 次 `character()`，**调用次数仍有结构冗余**。

### C-2 候选与判据

| 编号 | 项 | 预期（调用数） | 风险 | 验收 |
|---|---|---|---|---|
| **A-1** | `getStackSpeedMods` 合并 heat/cold 读取（本地 `ch = self.character()`） | 消 ~7.2 万 `character()` | 低 | 调用数 + 三闸 |
| **A-2** | 生成器趟：同函数内 `self.character()` 重复调用局部绑定 | 消 ~14 万 | 低-中（须排除副作用/可覆写改状态） | 调用数 + 三闸 |
| **A-5** | `_hasBehaviorMethod` 缓存（复用 C6 派发矩阵；`set_script` 须清表） | 消 5–6 万 | 中 | 调用数 + 三闸 |
| **A-4** | `EnumDict.__getattr__` 残量 → 直接下标 | 2–4 万 | 低 | 调用数 |
| **A-6** | `isItemAffected` 空间预筛（先 bounding box 后逐格） | 视分布 | **中（语义面：影响判定）** | **必须逐位等价** + 三闸 |
| **A-7** | `_iter` 残量（float/dict 形态） | 低 | 低 | 调用数 |
| **B-1** | 装配复用实验（先量深拷贝成本） | ~13% 装配占比 | 中 | 单场微基准 |

**优先级**：A-1+A-2（同一类变换，0.5 天）→ A-5（1 天）→ A-4（0.5 天）→ A-6（可选，1 天）→ B-1（实验）。
**合计预期**：A-1+A-2+A-5 消 **约 26 万调用/3 场（top30 的 22%）**。

## D 纪律与验收（本项目的血泪条款）

| 纪律 | 为什么写这条 |
|---|---|
| **账本 mtime 必须晚于代码提交** | `ff755e0c` 曾声称「1690 账本晚于提交」，实际差 1.5 小时——本项目唯一一次真的骗过自己 |
| **编译态结论必须证明 pyd 比源新** | `build_cython` 曾「pyd 存在即跳过」，导致 M1-1/M2 的「重编」全部空转；现用 mtime 判定（`--list` 报「全部目标新鲜」即证据） |
| **只报交错 A/B 比值，不报跨机绝对值** | 本机 `process_time` 刻度 15.6ms + 睿频抖动，p50 分辨率 ±4–10% |
| **单点微基准要加大 n** | 200k 次时的跳动是刻度噪声；800k–1M 才收敛 |
| **不许改判据**（`canonical_stream`/`render_lines`/语料）来变绿 | 改判据 = 作弊，比不修更糟 |
| **不许重生成夹具** | 会造出 13 场假红（`affected` 空、`stamina` 5.0、多 `label_rng`） |
| **`--force` 不可与 `--skip-godot` 同用** | 删了产物不补 = `gdcore 缺产物` 假阳性 |
| **`--cases-json` 不可传全量夹具** | 脚本会写回覆盖它（已被踩过一次） |
| **大文档禁止「读局部 → 整体写回」** | 曾因此截掉 45 行（已 `git checkout` 恢复） |

**三闸**：seed 双态（`20260923≡907`、`42≡1042`）→ REG 九场 → 60 场；**1690 走里程碑**（约 20 分钟）。
**A 类新增主判据**：`bench_sim --profile-out` 的调用数下降 ≥80%（绕开墙钟地板）。
