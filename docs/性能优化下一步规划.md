### 0.1 判定阈值（本轮修正，**取代旧的 10% 门**）

旧台账用「整场 p50 降 ≥10%」当有效性判据。实测噪声地板（同配置 n=40 重复 6 次）：

| 口径 | 极差 | stdev | SEM | **3σ 可辨** |
|---|---|---|---|---|
| `mean_ms` | 3.49% | 1.25% | 0.51% | **1.52%** |
| `p50_ms` | 7.18% | 3.71% | 1.51% | 4.54% |

**`p50` 的读数落在 `process_time` 15.62 ms 刻度的整数倍上**（实测一半 203.1、一半 218.8），
它的散布一半是量化噪声。⇒ **10% 那道门不是太高，而是用错了口径**：

| 场景 | 判据 |
|---|---|
| **整场改动** | `mean_ms` 降 **≥2%**（3σ=1.52%，留余量）；拿 `p50` 报 2% 级结论一律无效 |
| **微基准（日常）** | **≥1.05x**；≥1.3x 只留给「要不要换语言」这种量级决策 |
| **<2% 的改动** | 进「待累积清单」，凑够 ≥2% 合并测一次（见 §4.4） |
| **零收益但零风险且降复杂度** | **免收益判据**直接合（`load_for` 属此类） |
| 判据本身（`canonical_stream`/`render_lines`/语料） | **永远不许改** |

## 1 纪律（血泪条款）

| 纪律 | 为什么 |
|---|---|
| 账本 mtime 与代码提交时间相近 | 曾出现「声称晚于提交，实际差 1.5 小时」 |
| 编译态结论必须证明 pyd 比源新 | `build_cython` 曾「pyd 存在即跳过」，多轮「重编」空转 |
| **吞吐结论必须附负载，或用 `cores_eff` 归一化** | 同命令场/s 可差 2 倍（5.5–11.7），历史上据此得出的「4w 饱和」「绑核无收益」全被污染过 |
| **改编译期类型/pxd 后必须全量重编** | 只重编热点模块 → `Item size changed, expected 576, got 24`，21 模块崩（本轮实证） |
| 单点微基准要加大 n | 200k 次时跳动是刻度噪声；800k–1M 才收敛 |
| 看剖面要看总量，不只 top30 名单 | 事件计数回归就是 top1，按名单看永远看不出 |
| `@property` 惰性视图的计数必须 O(1) | 每 tick 访问聚合视图 = 全量物化 |
| 不许重生成夹具 | 会造出 13 场假红 |
| `--force` 不可与 `--skip-godot` 同用；`--cases-json` 不可传全量夹具 | 假阳性 / 脚本写回覆盖 |
| 大文档禁止「读局部 → 整体写回」 | 曾因此截掉 45 行 |
| 判否前先确认判据测的是不是同一件事 | 「object 槽无收益」被用来否定「数值槽」，是循环论证 |
| **进程池不能从 stdin 跑** | Windows spawn 重导主模块；探针必须落文件 + `if __name__ == "__main__"` |
| **全量里程碑必须回读账本 `match` 分布** | 「1690/1690」被声明三次，账本实为 1628+62「py 缺产物」——只报总数=没验（§7.1） |
| **编译层回归必须双臂（pyd vs GD_PURE_PY）对跑** | 62 场群崩溃纯 py 臂全绿，单臂永远定位不到（§7.2） |
| **pxd/生成物不可手改** | 重跑生成器即回填；修复必须落在生成器层（`_L2_BLOCKLIST`） |
| **构建清单必须显式排除包根辅助模块** | 否则 `_registry.pyd` 等遮蔽纯 py 语义 → 全树导入段错误（§7.3） |
| **热路径的「探针成本」≠「可省成本」** | 探针折算 43.4 ms，D1 全类型化后实省 1.7 ms，**差 25 倍**（§4.1） |
| **有风险 ≠ 不做，但先备份** | 顺序是「commit+**push** → 隔离分支 → 偏移检测 → 修实现 → 修不动才退」（§4.5）。前提是语义偏移**可检测**（1690 逐行 + 三闸），本项目具备 |
| **高成本方向先要「可测假设」** | G2（C++ 重写）被要求先回答「省哪一项、省多少」；本轮已证伪「消除调用边界」这个理由（编译态只剩 6.1 帧/tick） |

**三闸**：seed 双态 → REG 九场 → 60 场；1690 走里程碑。

## 4 下一步：做什么、什么顺序

> 本节的排序依据是**实测占比 × 可兑现性 ÷ 成本**，不是猜想的收益。
> 成本：S ≤0.5 天，M 1–2 天，L ≥3 天。判据统一用 `mean_ms` 交错 A/B（≥2%）；
> 零风险且降复杂度者免测（§0.1）。
>
> **方向池分两段**（2026-11-14 起）：
> - **A–F 类**：低风险，直接做。
> - **G 类（§4.3 末尾）**：**高风险高收益，但不再是"不敢碰"**。
>   走 §4.5 受控试错协议——先 `commit`+**`push`** 备份，再在隔离分支动手，
>   语义偏移先尽力修实现，修不动才回退。**试错记录进 §4.6**，失败也留证据。
>
> G 类排在 A–F 之后是**前置依赖**，不是"不敢"：详见 §4.3 G 类末尾的三条理由。

### 4.1 成本地图（2026-11-14 凌晨实测，负载 6.5%，基频 1600MHz 降频态）

> 这一节是本轮**新增的事实基础**。旧的 §4 是按「猜想 + 微基准」排的，D1 落地后实测只有 −0.8%，
> 证明那些猜想的量级都错了。所以本轮先把「钱花在哪」测清楚，再排序。

**单场 212.5 ms 的构成（full 模式 = 对齐/验证/产品路径）**：

| 块 | 占比 | 实测依据 |
|---|---|---|
| **trigger 触发链** | **45.2%** | 纯 py 臂打补丁计时：215–248 次/场，1380–1890 µs/次，占 `run` **45–50%**（`tools/bench_trigger.py`） |
| **事件系统** | **20.6%** | full vs light 逐场配对（24 对，中位比 0.794）；`logEvent` 1493 次/场 × ~28 µs |
| 冷却推进循环 | ~18% | 93k item-ticks；D1 已类型化，实测仅 −0.8%（§4.2） |
| **装配** | **11–20%** | `bench_assemble` 64.9 ms / run 257.7 ms；light 态 58.7/297.9 = 19.7% |
| 其余（几何/计时器/Buff） | <5% | — |

**关键教训（本轮踩到，必须记住）**：

> 热路径的「探针成本」≠「可省成本」。在真实引擎态测：`character()` 11.8 ms + `getSpeed()` 17.6 ms
> + `getHeat/getCold()` 12.3 ms = **43.4 ms/场（20%）**，但 D1 把这**全部类型化后只省了 0.8%**。
> 差 25 倍。原因：CPU 的分支预测/乱序/缓存已经把这些属性访问摊平了，微基准里「每次 getattr 独立付钱」
> 的模型在真实循环里不成立。⇒ **判据只认整场 `mean_ms` 交错 A/B，不认探针折算**。

#### H 类：两个结构性方向的定论（2026-11-14 凌晨实测后回答）

> 用户问了两件事：① 有办法让模拟器**彻底成为 C++** 吗？② 能否在**保证语义一致**的前提下
> 让战斗逻辑更快？下面用本轮实测回答，**结论不是"不敢做"，是"已测出不成立"或"成本收益不符"**。

##### H1「彻底 C++」——技术上可行，但收益已被三层实测封顶（成本 10.8 万行）

**规模底数**（本轮实测）：

| 项 | 数量 |
|---|---|
| `gd_core/` 模块 | 158 个 / 6554 行（含核心四类：`CoreItem` 3938、`CoreCharacter` 2070、`CoreCombat` 546、`CoreBuff` 553） |
| `gd_core_items/` 模块 | 505 个 |
| 转译后 Python | **108,455 行** |

**收益上限被三层封顶**：

| 层 | 实测 | 含义 |
|---|---|---|
| ① 调用边界 | 编译态每 tick 仅 **6.1 个 Python 帧**（纯 py 臂 455.9）；帧开销上限 **0.7 ms/场 = 0.3%** | 且这 5552 帧**全部在 `simulator/gd_core_engine.py`**（`logEvent`/`kernel()`/事件对象 `__init__`），内核里几乎没有 |
| ② PyObject 拆装 | §11.7 整链 C 化 **1.07–1.10x** | 这是已有的最接近「C 语义」的实测 |
| ③ 内存布局 | 规模曲线两次测量超线性比 **0.35–0.87**（**亚线性**），R²=0.55 | 物品数涨 7.3x、每千 tick 成本只涨 8.7x ⇒ 缓存局部性不是主导 |

**结论**：彻底 C++ 要重写 10.8 万行 + 承担无限期语义修复成本，而三层证据给出的**乐观上界约 1.3–1.5x**，
其中 ③ 还是「亚线性」——意味着布局优化这条路本身收益存疑。
**这不是"不敢碰"**（G2 的受控试错协议仍然有效），而是：**先要把「C++ 能省哪一项」变成可测假设，否则 XL 成本赌未知数**。

> 若仍要做，**推荐的不是"彻底"，而是「热路径 C 化」**——把 `CoreCombat.physicsTick` + `trigger` 链这两段
> （占 45.2%+18%）用 C 重写成单个函数，物品脚本逻辑保留 Python。这样只需触及 ~2000 行，而非 10.8 万行，
> 且语义面窄（无物品脚本覆写），可检测性最高。**这已作为 G2 的推荐降级形态记入。**

##### H2「战斗逻辑更快且语义一致」——**已经穷尽，本轮又证伪两条**

## 7 事故史（2026-11-13 晚，D1 里程碑揭出；完整过程见归档）

> 本节压缩为**教训**。完整追查过程（62 场群崩溃、毒树段错误、robocopy 误删恢复链）见
> [_archive_台账_20261113_791行.md](_archive_台账_20261113_791行.md) 与 git log `8c5a3cc7`/`e9251b68`/`4c9eb066`。

### 7.1 ⛔ 假绿记录（最该记住的一条）

「1690/1690 全绿」被声明过**至少三次**，但权威账本 `alignment_expand.json` 当时记的是
**1628 三方一致 + 62「py 缺产物」**。缺口跨多次声明持续存在，没人发现——
因为声明只看了**场次总数**，没回读账本的 `match` 分布。

**规则**：全量里程碑的验收必须同时满足
①账本 `perCase` 里每条 `match` 都是「三方一致」②账本 mtime 与声明同时刻。
只报总数 = 没验。

### 7.2 62 场群崩溃：三元组合的编译层回归

`super(): __class__ cell not found` @ `Greatsword_2.getStaminaCost`。触发条件是**三元组合**：
`cpdef double getStaminaCost`（§11.4 为闭环实验引入）+ plain 子类 `def` 覆写 + 零参 `super()`。
纯 py 臂同场 1/1 全绿 ⇒ **语义层无恙，是编译层回归**。`binding=True` 救不了。

**修复**：`getStaminaCost` 进生成器的 `_L2_BLOCKLIST`（退 plain def 动态派发）——
让 §11.7 早已判为 1.07–1.10x 的微收益换正确性。崩场复验 0/1 → 1/1。

**教训**：①三元组合类回归必须**双臂（pyd vs GD_PURE_PY）对跑**才能定位；
②`binding=True` 修完 binding=False 事故后未做 62 场专项复跑——三闸不覆盖该路径；
③pxd 是**生成器产物**，手动改会被下次生成覆盖，修复必须落在生成器层。

### 7.3 毒树事故：捆批重编把包根辅助模块编成了 pyd

§4.3 捆批（D5/D6/D8）全量重编时，构建清单从「存活 pyd 反推」，把 `_registry`/`_bootstrap`/
`_colors`/`__init__` 这些**包根手写辅助模块**也编成了 pyd → 加载器 pyd 优先遮蔽纯 py 语义 →
全树导入段错误。**当时所有旗标二分全部无效**，因为测试树本身被污染。

**护栏**：`build_cython.py` 新增 `_FORBID` 四文件拒绝闸；构建清单固定为 664 模块
（`_all_list2.txt`）。

### 7.4 里程碑终态（2026-11-14 00:50，真绿）

干净树（662 模块无旗标全量重编 + `_L2_BLOCKLIST` 修复）上 `--force` 全量重模拟：
