# C++ 模拟器下一阶段优化评估

日期：2026-11-22。先展开候选，再评判价值；本清单中的性能收益均是待验证假设，只有已部署版本的数字属于实测。候选之间可能重叠，不能把预期收益相加。

## 当前基线和目标

评估时的默认训练DLL为 `541238b57e2e18ce258a0afa9f548115761da28f4a1c119812277b4c0dae2983`，已包含成员指针纯属性读取、回调边界内角色状态复用、静态集合数值消费者折叠。当时最新一轮相对d3的24对AB／BA：CPU配对中位耗时降低2.0308%，墙钟降低2.2849%，三组方向均正。2,604场原版逐事件及逐场C++事件哈希一致；首份24批最低130.4157场/秒，20%负载拟合143.1494场/秒。上述两类速度口径不能混用；后续执行结果见文末。[当时部署后复核](../output/_v1110/native_perf50/static_collections_bundle/post_install_verification.json)

目标为20%负载换算200场/秒。以本次拟合点作规划，仍需吞吐提高39.7%，即每场耗时降低28.4%。因此应同时保留便宜的小组合和能减少整段运行时工作的结构改动；不因单笔收益被噪声遮住而丢弃，也不承诺某项未经测量的百分比。

新采样2,015栈，2,014个有回放根。按调用栈互斥归属：触发／效果链855（42.45%），物品／宝石装配366（18.17%），其余帧内683（33.91%），其余初始化／导出110（5.46%）。叶节点中，字典与哈希131、通用方法88；TLS运行库59，其中55的首个非运行库调用者是生成的静态属性读取。函数内联会改变叶节点归属，这些样本不等于独立收益，也不是收益硬上限。[原采样](../output/_v1110/native_perf50/static_collections_bundle/profile_depth64.json) · [可复算汇总](../output/_v1110/native_perf50/static_collections_bundle/brainstorm_profile_summary.json)

目前仍是固定物理帧推进，帧内通过事件总线传播触发效果。已经有原生桥接、缓存方法表、直接字段访问、内嵌计时器和部分紧凑布局；“再做原生化／加缓存／加稀疏索引”必须指出超出现有实现的具体改变。

## 候选全集及逐项判断

成本“小／中／大”包括实现与证明等效的成本；价值为相对当前版本的投入优先度，不代表保证收益。“优先原型”允许先做局部差分与成本筛查，不要求直接支付完整PGO和全量发布成本。

## 推荐执行路径

第一包选择01、02、03、31及必要的04：先从“静态属性TLS＋setup固定表”这一条路径下手。新增点是避开常量getter的TLS访问、消除遍历用集合、批量初始化；不是重复本轮数值长度折叠。容易限定语义，跨装配和战斗触发链都有实际证据。05可先做独立局部表示原型，再决定是否带入，避免首包范围失控。

结构主线优先14＋09＋10：选一种有代表性的武器触发／伤害链，比较定型入口与现有原函数，记录整条链成本、快路径覆盖率、回退和分配次数。先少量方法做纵向闭环，再扩展覆盖；不能把“所有方法仍回退”算验收成功。此主线更接近200目标需要的约28%总耗时降幅，应持续投入，而不是等所有微收益做完。

另一条中等成本路径为27＋28＋30，针对装配几何查询和联动；19＋17＋20作为运动路径备选。每次只让一包进入正式测速，避免编译／计数污染比较。稀疏计时器23、事件调度41与精确快进42保留，但必须明确比旧失败方案少了哪些维护成本或多了哪些等效证明，才进入完整构建。

小收益允许按同一热点组合，整体相对当前基线测得收益即可；并不要求每项都单独显著。混合包只报告组合收益，有必要定位贡献时再逐项撤回。对含糊结果按预先声明的有限补测处理，所有首份正反结果保留，不持续重测直到满意。

## 验证与停止条件

有确定性风险的结构变化前，先提交并核对远端已验收源码及DLL。局部原型用实际当前DLL作独立真值，检查异常输入、可变别名、未知接收者、回调嵌套、同帧新增／停用／重启、对象ID、RNG、浮点位及异常标志。通过局部语义与成本筛查再做完整构建；局部筛查不替代整场结论，也不设武断的最低收益淘汰线。
