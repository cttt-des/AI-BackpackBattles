# 调研报告 02：状态表示与动作空间设计

> 问题-方法导向。回答：**483 个异构物品 + 7×9 背包网格 + 5 槽商店，状态和动作怎么编码，策略网络才能学得动**。
> 调研对象：AlphaStar（Nature 2019）、OpenAI Five（1912.06680）、绝悟（1912.09729 / 2011.12692）、ByteRL（2303.04096）、LoCAM 竞赛（2305.11814）、Super Auto Pets 开源系（sapai-gym 等）、Slay the Spire RL 系（STS-RL / sts2-rl-agent）、Neural MMO、TransfQMix（2301.05334）、SMAC 系 GNN（DCG/DICG/GACG）。

## Q1 异构物品集合的编码

**问题本质**：物品是类别特征（483 类），且有尺寸/稀有度/数值属性/背包坐标等结构化字段；编码方式直接决定样本效率与泛化能力。

**方法谱系**：

| 方法 | 出处 | 做法 | 评价 |
|---|---|---|---|
| 类别序归一化 | 开源 STS 项目（sts2-rl-agent 的 card_id/(N+1)）、SAP 系 one-hot | 把 ID 当标量或 one-hot | 开源通病：无语义先验，样本效率低；本架构明确不采用 |
| 实体列表 + transformer | **AlphaStar** | 每单位一行特征（类型嵌入 + 属性 + 位置），transformer torso 编码 | 与 483 异构物品最匹配；实体数可变用 padding+mask |
| 共享嵌入 + 阶段参数 | **ByteRL**（LoCAM 冠军） | 构筑/战斗两阶段网络共享卡/英雄嵌入，阶段指示 δ 切换 θ_CB/θ_BT | **构筑类游戏直接验证有效**；本架构的 θ_embed 共享即源于此 |
| GNN 物品图 | SMAC 系（DCG 1910.00091、DICG 2006.11438、GACG 2404.10976）、RTS attention 图（2105.10211） | 状态分类 + 自注意力图 + QMIX 类值分解 | 邻接协同（Backpack Battles 大量物品有相邻触发）天然是图边；TransfQMix 证明**图编码可跨规模迁移**（换背包尺寸/物品池时有用） |

**对本项目**：物品 = 实例表一行（item_id 嵌入 + 属性 + 坐标 + 朝向）→ transformer 编码集合；背包邻接关系用 GNN/attention 读取。嵌入初始化用 KG 预训练（见调研报告 05）。

## Q2 背包网格的空间编码

**问题本质**：7×9 网格既有局部几何（物品占格、旋转、容器嵌套）又有全局结构（相邻协同、整体平移）。

**方法谱系**：

- **空间特征层（AlphaStar 式）**：网格作为多通道特征平面（物品 ID 平面 + 旋转/容器归属/增益标量平面），CNN/小 transformer 直接消费；orbit-wars-torch 证明 grid 状态天然是 (B, C, H, W) 张量。
- **图节点式**：格子=节点（位置特征 + 占用物品嵌入），邻接边=相邻关系；优势是平移等变、参数省、跨尺寸迁移（Q1 表）。
- **混合（本架构推荐）**：transformer 编物品集合（语义）+ 空间层/GNN 读几何（位置）+ LSTM core 记跨回合经济上下文（AlphaStar 的深层 LSTM 对应我们的 18 回合记忆）。

## Q3 动作空间爆炸的压缩

**问题本质**：买×放×卖的组合是乘积空间（5 商店槽 × 64 物品 × 63 格 × 2 旋转 …），扁平离散化不可学。

**方法谱系**：

| 方法 | 出处 | 做法 | 效果 |
|---|---|---|---|
| 扁平 Discrete + 掩码 | sapai-gym（63 动作）、STS-RL（32 options+mask） | 预定义动作集，MaskablePPO | 最省心，但动作集需人工设计；适合动作结构简单的游戏 |
| **自回归分解 + pointer** | **AlphaStar**（动作类型→选单位→目标单位→x/y→排队）；**OpenAI Five**（选单位→技能/物品→目标→偏移） | 每步动作 = 条件化的小 head 序列，pointer network 从实体列表"指选" | 把 ~10²⁶ 合法动作压成几个小 head；**构筑游戏远比 SC2/Dota 简单（战斗自动无动作），天然适配** |
| target attention | 绝悟 1v1（AAAI 2020 四关键词之一） | 从大量候选中注意力挑相关目标 | 与 pointer 同族，工程上更省 |
| options 压缩 | STS-RL（32 维 options+mask） | 高层 macro-action | 与子策略分层（调研报告 05 Q4）合流 |

**对本项目**（架构文档 §3.4 已定）：`action_type → pointer(商店/背包实例) → (row,col) → rotate` 自回归链；合法性掩码内建于引擎 step 之前，训练/推理共用同一代码路径（防崩 checklist 条目）。

## Q4 放置子问题：学还是搜？

**问题本质**：放置是几何约束满足 + 协同优化，RL 学它样本成本高；但摆错直接输战斗。

**方法谱系**：

- **完全学习**：sapai-gym 把拖放也离散进动作空间——SAP 棋盘小（5 宠位）可行；BPB 7×9 网格组合爆炸，不推荐全学。
- **完全搜索**：ottoblep/backpack-battles-solver 把放置建模为组合优化（random/greedy + 时限 + 多线程）——可生成 placement 监督数据。
- **混合（本架构推荐）**：策略输出"买哪些/卖哪些/带什么进战斗"，placement 由 solver 求解或专用小网络 + 引擎合法性过滤；两子问题解耦（sapai 范式："学到的 shop 策略 + 免学习的战斗评估"）。

**注意**：背包整体平移（shift 四方向）是真机制（改变战斗布局，`Inventory.gd:920-947`），引擎必须实现，但不一定要作为策略动作暴露——可作为 solver 的合法操作。

---

## 结论

1. 观测 = transformer（物品集合）+ 空间层/GNN（背包几何）+ LSTM（回合记忆）；嵌入 KG 初始化（报告 05）。
2. 动作 = 自回归分解 + pointer + 引擎内建掩码；放置与 solver 解耦。
3. 类别特征一律嵌入化，不开 ID 归一化倒车。
4. 这些选择与 ByteRL（构筑类游戏唯一击败 top 人类主播的系统）的设计同构，非拍脑袋。
