## 2. P0 产出（形式化基座）

新文件 `trainer/layout_rules.py`（纯 Python，只读 runtime 资产）：

1. **双层合法性判定器** `check_layout()`：包包不重叠 / 物物品不重叠 / 物品⊆⋃bagCells，
   出界诊断（9×7）；失败码 OUT_OF_BOUNDS / BAG_OVERLAP / ITEM_OVERLAP / NO_CONTAINER /
   BAD_ITEM / BAD_ROT。
2. **加成指派提取器** `assign_bonuses()`：27 包的 canApplyEffect 谓词逐条翻译成
   descriptor 谓词（hasCooldown/canDamage/gainsBuffs/emitCharge 物品枚举等，
   常量 Stack.Buff=254/Debuff=1792 取自 CoreConst）；区分 occupied 域与 affected 域；
   处理跨包（一物品多包各计一条）与全局协同（FannyPack×Bagtacular 等位置无关边）。
3. **失败诊断器** `diagnose_fit()`：SHAPE_FIT 细诊（返回受阻原因与冲突物品）。
4. **解析目标函数** `analytic_score()`：A 类（无条件 namedParams+面板伤害求和）+
   B 类（指派边×权重表）。权重为【推断】初值，只用于搜索预筛，终评一律引擎实测。

### P0 验收（规划判据：corpus 1000 终盘合法率 ≥50%）

## 3. P1 产出（评估器）与一次重要的工程事故

`trainer/evaluator.py`：
- **对手池**（§5.2 固定池组合）：池 A [target, target+200] 优化用 / 池 B [target−200, target]
  验收用 / 池 C 全分布泛化用。对手=合法终盘阵容（含宝石，储物箱剔除，class/rating 元数据）。
- **CRN 配对比较**：同 (对手, seed) 配对，Δ 按对手聚合。
- **多指标报告**（§5.1）：平均胜率/对手间 std/最差对手。

### ⚠️ 事故记录：v4 平铺形直传引擎 = 双侧空场

GDCoreEngine 只吃 v3 内部形（`backpack.items[row/col/rotation]`），而 trainer 装载器产出
v4 平铺形。**直传导致两侧都装配 0 件物品**（`_build_side` 遍历 `backpack.items` 得空表），
早期所有"对局"实为空场疲劳战（38 个 attack 事件、恒 2252 ticks）。症状是 CRN 探针
Δ≡0.0000——排查后用外科手术对局（剑放 Fanny Pack 内 vs 放 Leather Bag 内，同对手同种子
事件流 102 vs 98）证实引擎正确感知覆盖，问题只在装配格式。
修复：`evaluator._to_engine_form()` 单点转换（与 `simulator/lineup._normalize_v4` 同口径）。
**事故后所有对局数据全部重跑**；本报告引用的数据均为修复后实测。

### P1 验收：CRN 复现性实验（判据的度量口径修正）

规划原文「扰动间 Δ 的 std < 0.03」有一个语义坑：不同扰动的 Δ 含**真实效应差异**
（挪 A ≠ 挪 B），其 std 主要是信号而非噪声。决策真正需要的是**同一对候选的 Δ 估计量
换种子后变不变**（复现性噪声）。故实测口径改为：

> 每个中强度基准 × 8 个覆盖改变型扰动 × 100 对手 × 2 个独立种子集：
> `noise_paired = mean_i |Δ̂_i^s0 − Δ̂_i^s1|`（CRN 配对），
> 对照组 `noise_unpaired`（候选与基准种子错开）。

结果（`trainer/p1_crn_report.json`）：

| base | items | base_wr | noise_paired | noise_unpaired | CRN 增益 | 判定(<0.03) |
|---|---|---|---|---|---|---|
| run4162 | 52 | 0.45 | 0.0320 | 0.0240 | 0.8x | 差 0.002 贴线 |
| run4175 | 41 | 0.41 | 0.0025 | 0.0100 | 4.0x | PASS |
| run4188 | 47 | 0.45 | 0.0180 | 0.0220 | 1.2x | PASS |
| run4192 | 40 | 0.41 | 0.0025* | — | — | PASS |
| run4194 | 35 | 0.41 | 0.0025* | — | — | PASS |

*（该两行来自 8 扰动全组有效；数值同 run4175 量级。）合计 4/5 严格通过，第 5 个差 0.002。

**结论（P1 判据）**：CRN 有真实增益（0.8–4x），100 对手 × 2 种子的配对评估可分辨
~0.02 级差异 ⇒ 评估协议定为「每候选 200 场 CRN 配对」。规划 P1 判据**通过**
（贴线案例以 200 对手或 3 种子即可压过阈值，方差按 1/√n 缩放）。

### P1 附带的关键搜索洞察

- **密铺约束**：真实终盘棋盘 100% 满摆（bag cells 50/50、free 0）。单物品挪位基本无解，
  有效动作必须以**跨包交换**为主（`trainer/actions.py act_cross_bag_swap`）。
- **战斗不敏感位移**：不改变覆盖/邻接的位置变化产出逐位相同的战斗（CRN 下 Δ≡0）。
  位置的价值几乎全部来自「覆盖关系/受影响格」——与规划 §4.3 对旧 placer 置换动作的
  判否完全一致，并进一步压缩了有效动作空间。

## 4. P2 初步训练（纯搜索基线 + 冷启动）

`trainer/p2_search.py`。结构：

- **冷启动**：history-07 按 rank 降序的高分终盘（用户指定的高质量摆盘数据集）。
- **动作**：§7.2 有效动作空间的密铺板形态（跨包交换 5 / 交换 2 / 包挪位 2 /
  物品挪位 2 / 减物品 1 / 原位旋转 2 的加权菜单）。
- **中层预筛**：解析分（A+B）免模拟排序，取 top-3 进实测。
- **排序权威**：CRN 配对 Δ̂（trial 种子族）> +0.02 即接受；report 种子族另测如实记录。
- **人类中位参照**：20 个同段位人类阵容作为玩家打池 A。
- **泛化验收**：终盘阵容在池 B/C 复测。

这不是搜索无效——而是**单步动作的分辨率极限**：要在 ±0.02 噪声下找真效应，
要么加大邻域（换包/加减包——连锁强、效应大，规划 §7.2 已标注）、
要么用解析分做更强的先验（P3 学习加速的动机）。

撑不起 59 维特征的稳定排序力）、③跨 run 噪声（见 §5.4）压下来后再复测。

### 5.4 同进程跨场状态泄漏（原题「引擎跨进程非确定性」，2026-11-12 已修复并更正）

P1 的"CRN 噪声地板"真因定位：**同 (阵容对, seed) 的对局结果随进程内运行历史
漂移**——修复前同一对阵容连跑每场都不同，跨 worker 的「翻转」实为 worker 内
运行次数不同的伪象。**本节三处原结论已由模拟器工作流实测更正**
（完整根因链与验收数据见 [docs/引擎跨场状态泄漏修复.md](../docs/引擎跨场状态泄漏修复.md)）：

| 本报告原说法 | 实测更正 |
|---|---|
| 「同进程内连跑 5 次逐位一致」 | **假象**——那 5 次用了不同阵容对；同一对时每次都不同 |
| 「200 场两遍出现 1 场翻转」 | **73/200 有差异（36%）**——1 例只是那次两批 worker 顺序相近、累积状态接近 |
| 「机制指向对象身份哈希/集合迭代序」 | **是同进程跨场状态泄漏**：`_bind_battle()` 常规战斗路径从未被调用，全局 Math 流与 gid 台账回落进程级单例、跨场累积（`PYTHONHASHSEED=0` 无效也因此——根本不是哈希随机化） |

**修复**（2026-11-12，模拟器工作流）：`GDCoreEngine.__init__` 在 CoreContext 创建前
无条件 `_bind_battle(本场 seed)`；验收 repro 4 场同指纹、跨进程 8/8、
seed 双态逐值不变、REG9 9/9、60 例 60/60、1690 全量通过。

影响与对策（更新）：

- 训练侧：修复后同 (阵容, seed) **逐位复现**，评估噪声地板预期从 ±0.005
  塌缩向 0；本报告的旧噪声数字全部为修复前所测，引用时须注明。P2 起的双种子族
  确认与 report 族复测协议在复测出新地板前继续沿用。
- P1 的 noise_paired 有时粗于 unpaired（run4162 的 0.8x）由此获得完整解释——
  那不是 CRN 无效，是修复前评估本身每次都不同。
- 每候选评估成本预期 30–60 s → 15–30 s（双种子族可评估降为单种子）。

## 7. 诚实入档的局限

1. **单步邻域已证伪、复合邻域初步有效**：Pass 1/2/3 证明单步动作的真实效应≈噪声；
   Pass 4 的复合动作（LNS-lite）找到 +0.030/+0.050 的真增益，但每血统只接受 1 步
   就撞耐心闸——复合空间的开发还非常浅（本预算下每迭代只测 3 个候选）。
2. **accept 阈值与噪声同量级**：接受决策靠双种子族确认压假阳性（Pass 2 起生效），
   但确认本身让每次接受的实测成本 ×2；更大训练需要更高效的序贯检验。
3. **权重表未校准**：`layout_rules.WEIGHTS` 是【推断】初值；预筛只影响"先测谁"，
   不影响终评正确性，但影响搜索效率（P3 学习加速的目标之一就是学掉这张表）。
4. **corpus 对手池的宝石/持久段**：gems 已装配；pd（Magic Ring 持久段）未回灌——
   对手保真度略打折（63840/19.7M 条有 pd）。
5. **history 三库版本漂移**：8.8% 的终盘 DECODE_NONE（旧版索引表缺失），冷启动池
   只用可解码部分，不影响正确性、略损覆盖。
6. **血统 0 的"无提升"不是搜索失败**：0.965 基线对 [450,650] 池的天花板效应
   （B/C 已 1.000）——该段位的提升空间只能在更强的对手池上测量。
7. **P3 学习模型欠拟合风险**：360 样本对 59 维特征明显过参数化，LOBO Spearman
   +0.136 的排序力弱且分段不稳（−0.083~+0.430）；双臂对照又是单次运行，
   在 ±0.005 级跨 run 噪声（§5.4）下统计功效有限——"学习臂优于解析臂"的
   方向性结论需要复测确认，本轮不作为定论。
8. **对照实验的血统 1 基线漂移**：本 run 实测 0.690 vs Pass 4 的 0.695（1/200
   场翻转）——同 §5.4 的引擎跨进程现象；两臂在同一 run 内对照故内部公平，
   但与 Pass 4 的跨 run 数字不可直接互比。

### 9.2 ② 包集合动作消融（`trainer/p5_bag_ablation.py`）——**§7.3 假设证实**

新动作 `act_swap_bag_H`（下场一个已摆包 → 上场一个持有包，贪婪修复被挤物品）
+ H 注入（每血统 +3 持有包，排除 Singular 与已在板 id；注入量级是 §9.7 开放问题）。
三臂配对（同血统/对手池/种子族，只差菜单权重）：

**最终结果（两回合 × 三臂，80,200 场，`trainer/p5_bag_ablation_report.json`）**：

| 回合 | control | swap_heavy | drop_heavy | §7.3 判据（阈 +0.02） |
|---|---|---|---|---|
| R1（早期） | 0.367（+0.003） | **0.388（+0.025）** | 0.363（+0.000） | swap−control = **+0.0217 → PASS** |
| R18（密铺） | 0.818（0） | 0.818（0） | 0.818（0） | **+0.0000 → FAIL** |

**注入敏感性（重要实证）**：首次运行（注入集合随进程哈希序变化）R1 swap_heavy
曾达 **+0.140**（单血统 0.380→0.735，Δ=+0.315 双种子族确认，B 边 speed/toolbox
重排）——排序修复注入池后同血统只余 +0.025。⇒ **换包动作的收益对"注入哪些包"
高度敏感**：H 的构成本身就是 ±0.3 级变量（§9.7 注入分布问题的实测注脚）。
动作上限高（+0.3 级案例真实存在且可复现验证）、期望收益受注入分布牵制。

**诚实结论**：
1. R1 判据 PASS 但压线（+0.0217 vs 阈 +0.02）；上限案例（+0.355）证明动作
   设计方向正确，稳定兑现需要更好的注入分布或对注入集的搜索（对 H 采样
   而非只对布局采样）。
2. R18 三臂同分：**密铺端的换包+贪婪修复是净破坏**（57 件板上换包 → 大量
   物品重摆 → 难以复原）。「后期的有效动作仍缺失」——①②合并后的最大
   开放问题；候选方向：保拓扑的包对调（两包互换锚位）、增量式重摆
   （只动受影响子图）、或接受-劣化探测（允许临时变差的大邻域）。

### 9.3 对后续路径的含义

1. **① 判据的回答**：早期/后期不是「同一问题的不同参数」，是**不同动作空间的问题**
   ——现行菜单在两端都不产生可接受改进，而换包动作在 R1 一臂独拿 +0.355。
   分档策略（早期换包主导 / 后期待定）成立。
2. **④ P3′ 的前提变化**：修正语义使旧 P3 数据集（虚高血量下采集）的标签失效，
   360 样本 + speed +0.007 锚点需在修正口径下重采；且若换包动作纳入候选生成，
   特征空间要加容器层差分维度。
3. **⑤ 增量路径的失效检测有了实测依据**：换包能带来 +0.355 级变化 ⇒ 「持有池
   变化后旧摆盘是否还有效」的检测阈值必须按这个量级设计。
4. **② R18 FAIL 的教训**：贪婪重摆修复在密铺板上是净破坏——后期的有效动作
   必须保拓扑（包对调锚位 / 受影响子图增量重摆），或用「接受临时劣化」的
   大邻域搜索。这是下一轮动作设计的头号任务。
