## 💎 导出阵容补全：镶嵌宝石 + 袋内物品（item_reader.py + gui/app.py + 重建 exe）

### 背景
v3 导出里 `gems`/`contents` 此前硬编码 `[]`。核查反编译源码确认二者都是场景树**真实后代节点**（非对象引用、无需桥接）：
- 镶嵌宝石：Item.gd:3042 `setGem()` → `sockets[id].add_child(gem)`，`sockets = $Icon/Sockets.get_children()`（Item.gd:309）→ 宝石位于 `物品→Icon→Sockets→Socket(GemSocket.gd)` 之下。
- 袋内物品：Item.gd:2553 `reparent(item, insideRotationNode)` → 位于 `袋子→insideRotationNode` 之下。

### 改动（core/item_reader.py）
- `_collect_items` 改为**递归下降**：传入 `parent_info` / `in_sockets` / `_visited`，结构性识别：
  1. `in_sockets` 子树（Sockets/GemSocket 节点）下的物品 → 宿主 `gems`（覆盖武器/护甲/袋子的镶嵌宝石，含 `Items/Exclusive/` 符文）
  2. 顶层直接子节点 → 顶层物品（含散落宝石）
  3. `is_bag` 物品子树（非 sockets）→ 宿主 `contents`
  4. 兜底：非袋宿主下宝石脚本判定 → `gems`
- 新增 `_build_info`（统一构造 ItemInfo，默认 `gems=[]`/`contents=[]`）、`_is_gem_script`（脚本路径判定，覆盖 `Items/Gems/`、`Items/Exclusive/`）。
- 深度上限 24、visited 防环。

### 改动（gui/app.py `_on_export_lineup`）
- `item_entry` 改用读取到的 `it["gems"]`，并**递归展开** `it["contents"]`（同 schema）。

### 验证
- 模拟场景树单测（stub pyautogui/yaml）全通过：Dagger 捕获 Ruby、Bag of Giving 捕获 contents=[Dagger]+gems=[Amethyst]、散落 Ruby 顶层且 gems=[]；导出 v3 被 `load_lineup` 接受，跑通真实战斗（宝石挂载生效）。
- 用系统 Python 3.14.5（含 tkinter）+ PyInstaller 重建 `dist/BackpackAI.exe`（后台任务 5EfWLe）。

### 已知边界（未扩大范围）
- **无脚本基类袋子**（如 Leather Bag/Coins/Shortbow/Goobling/Superior Ring）原读取器按 `res://Items/` 脚本判定物品，本就捕获不到其本身及袋内物品——这是既有限制，本次未改（需节点名判定，风险较高）。有脚本的袋子（Bag of Giving/Toolbox 等）正常捕获。
- 袋内物品在模拟器内**仅用于物品名解析**（`resolve_items` 递归走 contents），combat.py 当前未把 contents 放进袋子内网格参与战斗——属模拟器侧未实现，非导出问题。
- contents 坐标为占位（袋内局部坐标未换算到背包网格，模拟器当前也未消费）。
