## 排名/杯数（rating）结算机制（逆向确认）
- 游戏无字面“杯”，真实结算对象是 `rating`（评分浮点，按职业/赛季存 `persistent["rating"+season][class]`）。
- 显示用 `getLeague_exact(rating)` → `league(整数段位) + 段内进度(0..1)`；玩家所见“杯数”= `int(leagueExact*100)`。
- 段位阈值 `leagueThresholds=[0,50,120,200,300,400,480,550,850]`，对应 Bronze/Silver/Gold/Platinum/Diamond/Master/Grandmaster/Grandma/??（ImpossibleWoodRank=-1）。
- **只在整轮 run 结束 `endRun()` 结算**（Game.gd 4571 `setRating(calcRunRatingForClass())`），不是单场战斗。
- 核心公式 `calcRunRating`（Game.gd 4449）：
  - base = `2*wins`；`tries>0` 时 `-0.5*losses`，`tries==0` 时 `-1.0*losses`。
  - 胜利奖励（非生存）：`losses==0` → +7.5(PERFECT_RUN_RATING)；`elif tries>0` → +5(MAX_WINS_RATING)；tries==0 无奖励。
  - 生存模式：`perfectRunBeforeSurvival`→+3.75；`losses==0`→+12；`elif tries>0`→+7；oldLeague>=Master 时 ×0.6。
  - 衰减/不对称：`curRating=(old+rating)*0.96`；若 change<0：`change*=0.6; curRating=old+change*0.63`（跌幅≈原负增量×0.96×0.6×0.63，强烈缓冲）。
  - 跨段晋升（`int(newLeagueExact)>int(oldLeagueExact)`）额外 +`RANK_UP_BONUS_RANKING=10`（leagueExact+0.10 等价奖励）。
  - clamp 到 [0, 849.5]（`leagueThresholds[Grandma+1]-0.5`）。
- 常量：`MAX_WINS=10, MAX_TRIES=5, ratingDecay=0.96, ratingVelo=0.63, RANK_UP_BONUS_RANKING=10`。
- 仅 `Mode.Ranked`（及 ranked-switch-mode）才 commit；`Mode.Lobbies`/`Unranked` 自定义规则 `commit=false`，不改 rating。
- 另有独立“奖杯 trophies”体系（MAX_WINS_TROPHIES=10 等），与 rating 无关。
- 注意：用户可能把局内 HUD 的 wins/tries 当成单场杯数；需澄清 rating 只在 run 末结算。
- 已向用户输出「杯数结算」清爽版总结（流程图 + 四步公式 + 段位映射 + 示例），强调：run 末一次性结算、净负缓冲≈×0.36、杯数=int(leagueExact×100)。
