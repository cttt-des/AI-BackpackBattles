### 转译器 (extract_items.py)

  不再被 `_item.<name>()` 前缀（找不到），改经 `_item._behavior_call("Name", ...)` 路由到行为执行器；

  removeMana/getMostStacks/isCooldownActive/sendCharge/chargeReceived/getAffectedItems_nocache
  → snake_case（引擎早已有这些方法，只是驼峰名没映射）。
- **数组方法**：`.pop_back()`→`.pop()`、`.duplicate()`→`.copy()`、`.append_array()`→`.extend()`、
  `.size()` 兜底→`.__len__()`；`for i in <expr>:` 统一包 `_range_or_value(...)`（修复 `for i in len(x)` 迭代 int）。
- **多行字面量解析**：collect_instance_vars 改为按索引收集续行直到括号闭合
  （修复 onready/const 多行 dict/list 被当成 `{`/`[` 断行 → _onready_init 编译失败被静默丢弃；
  现在 Wand availableBuffs、各物品 chargeCells=[Vector2(..)..] 都能正确转译）。
- **Vector2/Vector2i** 加入 BUILTINS + BEHAVIOR_GLOBALS（`_Vector2(tuple)` 类，支持 .DOWN/.rotated()）。
- `getAffectedItems_nocache` 等专用映射；`updateShaderRotation` 加入视觉跳过清单。

## 物品中英文名全面修复（错位 96 + 补译 199，518/518 全覆盖）

### 问题根因
`simulator/extract_translations.py` 用「比例线性映射」对齐 en/zh 字符串池（round(k*len_zh/len_en)）：
- en 池 TITLE 正则只匹配到 61~84 个英文名（大量含数字/符号物品名漏掉）
- zh 池 HAN 正则混入非物品中文（158~215 个）
- 两池数量悬殊（ratio 2.5+），映射严重错位（Stone→存钱罐、Lucky Piggy→笨重巨剑、Sun Armor→炽热长矛）
- 只有 `assets/zh_override.json`（308 条人工核对）可靠，其余 pairs 全是错的

### 已尝试并放弃：.translation 二进制精确解析
`C:/tmp/bb_tr/Sheets/CSV/*.translation` 是 Godot 3 PHashTranslation（RSRC 资源）：
- 结构：hash_table(质数大小 uint32 数组，元素=bucket 偏移或 0xFFFFFFFF) + bucket_table(完美哈希桶:
  size, func, 每 elem={key, str_offset, comp_size, uncomp_size}) + strings(smaz 压缩流)
- smaz 词典已从 godot 3.6 smaz.c 提取（C:/tmp/bb_tr/smaz_dict.py，RCB 254 项，解压函数可用）
- 已定位：en size@301=389 ht@305，zh size@324=389 ht@328（含 locale=zh_Hans_CN 占位）
- **未攻克**：bucket elem 的 key/off/cs/us 字段对齐与 hash 验证全部失败，且 strings 块起点 (8521/8488)
  整块解压 en 只出 63 个物品名、zh 完全失败。判断该格式为 Godot 导出专用变体，手工解析不可行，已放弃。
- 结论：中文名不依赖 .translation，改用人工翻译 + override 锚点

### 修复（tools/fix_zh_names.py + fix_zh_names2.py）
1. **96 个错位项修正**（当前 zh 是他人 override 中文名的）：如 Stone→石头、Lucky Piggy→幸运存钱罐、
   Sun Armor→太阳护甲、Magitecc Armor→魔法科技护甲、Goobling→黏宝宝、White Pawn→白兵(国际象棋术语)
2. **199 个未翻译项补齐**（英文名直译+游戏机制+社区名）：如 White-Eyes Blue Dragon→青眼白龙、
   Thors Hammer→雷神之锤、Wolpertinger→鹿角翼兔、Dancing Dragon→舞龙、Chili Pepper→红辣椒
3. **同名消歧**：Long Spear→长柄矛、Wolf Emblem→狼徽记、Puzzlebag L/S/Z/T/J→拼图背包·X
4. 全部并入 `assets/zh_override.json`（现 602 条，成为唯一权威中文名表）
- 结果：518/518 物品有中文名，0 错位，0 重复
- `simulator/i18n.py` 从 battle_items.json 的 zh 读取，GUI 直接生效（已用 zh_name() 抽查验证）

### 关键约定
- **zh_override.json 是中文名唯一权威来源**；battle_items.json 的 zh 由 override + 翻译生成
- 补充翻译时用 fix_zh_names*.py 模式：英文名直译 + 游戏机制，先查 override 词汇避免重名

## exe 缺 tkinter 修复（打包必须用带 Tcl/Tk 的 Python）
- 症状：BackpackSimulator.exe 启动报 ModuleNotFoundError: No module named 'tkinter'
- 根因：上次用 managed/venv Python（3.13.12）打包——该 Python 无 Tcl/Tk（`import tkinter` 失败），
  PyInstaller 打包时没有 tkinter 模块 → exe 内缺失
- 修复：改用**系统 Python 3.14.5**（`C:/Users/Windows/AppData/Local/Microsoft/WindowsApps/python3.exe`，
  site-packages 在 `AppData\Local\Python\pythoncore-3.14-64`，自带 tkinter 8.6 + PyInstaller 6.22.2）重新打包
- 验证：pyi-archive_viewer 确认 exe 内含 pyi_rth__tkinter + _tcl_data\*.tcl；启动 exe 进程存活 GUI 正常
- ★ 经验：**打包 BackpackSimulator 必须用系统 3.14.5**（唯一带 tkinter 的 Python）；build_simulator_exe.py
  注释也说明了这一点；managed/venv Python 只能用于无 GUI 的库/CLI
