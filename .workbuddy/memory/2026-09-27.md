## ★★ 差异分级「NUMEQ」——本轮最有价值的发现

两侧**数值类型表示**本来就可能不同，故判据不是「相等/不等」二值，而是三级：
`SAME` / `NUMEQ`（仅 int↔float、数值相等）/ `DIFF`（须逐条归因）。

- 根因：**GDScript 的带类型变量在赋值时强制转换，Python 不会**。
  `gd_core/CoreDamageResult.gd:18` 声明 `var damage: int`，`damage *= getCritSeverity()` 后
  GDScript 存 `int 4`、Python 存 `float 4.0` → `damage=i4` vs `damage=4.000000`。
- 聚合：`DealDamage.damage` 1174 / `Health.amount` 527 / `CriticalDamage.damage` 35 /
  `Spikes.amount` 16 / `Poison` 9 / `Block` 7 / `Blind` 5 / `Vampirism` 4 / `Cold` 3。
- ★ **NUMEQ 不等于「无害」，但该判据仍然够强**：若某处被强制转换的值**不是整数**，
  GDScript 会**截断**而 Python 保留小数 → 数值不等 → NUMEQ **立刻降级为 DIFF** 并被指名。
  故 `DIFF 0` 的精确含义是「**这 56 局触达的转换点上，值恰好都是整数**」，
  **不**等于「整条路径不存在非整数强制转换」。下一步要把事件对照扩到 517 件逐一上场。

# 三轮：转写缺口覆盖（闸门 17 + 三段静态扫描）

**触发**：用户只发来一行 `TypeError('float' object is not callable')`。
一行报错 → 挖出「**转写缺口从未被系统性覆盖**」这一整类问题。

## 根因链

`output/repro_allitems.py`（临时复现器，517 件逐一上场）跑出 **19 件物品一用就崩 / 六类根因**，
而 16 道闸门此前**全绿、一行红都不报**。原因：GDScript 侧闸门 9 把 517 件逐一带上场了，
Python 侧（**模拟器真正跑的那一份**）只跑过 8 套阵容的 56 局。**面完成了，但没走遍。**

| # | 根因 | 件数 | 报错 | 为什么 GDScript 侧正常 |
|---|---|---|---|---|
| A | 变量名遮蔽基类方法 | 4 | `TypeError: 'float' object is not callable` | GDScript 成员/方法**两张表** |
| B1 | `call_deferred` 未映射 | 10 处 / 8 件 | `NameError` | Godot 原生提供 |
| B2 | `typeof` + `TYPE_VECTOR2` 未提供 | 12 件（棋类） | `NameError` | GDScript 内置 |
| B3 | `tr` 未提供 | 3 件（仅描述文本） | `NameError` | GDScript 内置 |
| B4 | `load` 未映射 | 1 处 | `NameError` | GDScript 内置 |
| C | `PCG32.randi` 缺失 | 1 件 | `AttributeError` | 原版裸 `arr.shuffle()` 走 Godot 实现 |
| C' | **整行丢失**（`find_block_end` 缩进误判） | 18 个文件 | `AttributeError: 'NoneType'` | GDScript 解析器不看续行缩进 |

**★ A 类的语言根因（本轮最重要的一条认知）**：GDScript 里
`GDScriptInstance::get` 查 **members** 表、`call` 查 **member_functions** 表，两表独立，
所以子类 `var speed` 与基类 `func speed()` 可以共存 —— `self.speed` 取变量、`self.speed()` 调方法。
Python 只有**一张**表 → 实例属性遮蔽类方法。取实例 = 取函数 → 调它即 `TypeError`。
实测 4 处撞名，**全是 `speed`**：ChessMaster / GirlPower / PerpetuumMobile / Sloth。
崩点在 `CoreItem.getSpeed()` 里的 `self.speed()`。

处置 = **生成器 R8 撞名消歧**（`speed` → `speed_v`），判据 =「本文件顶层 `var` 名 ∩ 继承链上的 `func` 名」。
**不**改内核方法名（破坏逐行可核性）、**不**改 `_rt`（运行期本就无法区分同名属性/方法）。

**★ B4 的隐藏事实**：`gd_to_py.py` 的 `load→_load` 规则写成
`(?<![\w.])load\s*\(\s*(?=\")` —— 要求 `(` 后紧跟**引号**，
但 `mask_strings()` 在改写**之前**已把字符串字面量换成占位符。
→ **该规则从写下起一次都没命中过**，垫片 `_rt._load` 一直是死代码。
放宽为 `(?<![\w.])load\s*\(`（全库无自定义 `func load(`，无冲突）。

**★ C' 的机制**：`gd_to_py.py::find_block_end()` 纯按缩进判块结束，
而多行字面量的 `}` 落在**第 0 列** → `_readyInit()` 被判为提前结束 →
`damageSource = CoreDamageSource.new().setItem(self)` **整行被丢**。
活例 `gd_core_items/Exclusive/WandofDissonance.gd`（该行顶格 `}` 之后）。修：加括号深度跟踪。

## ★ 本轮新纪律：判据的判据

**「0 命中」有两种解释 —— 「真的没有」或「扫描器坏了」，两者输出一模一样。**
凡「0 命中即通过」的判据，必须配**可证伪的正对照**（删掉一条真缺口，要求它报出来）。
这条纪律当场抓出**三个扫描器 bug**：

| bug | 后果 |
|---|---|
| `_resolve_ext` 只认 `"res://Items/…"`，不认 `"res://gd_core/…"` | 继承链断 → A 段 GDScript 侧恒返回「无」 |
| `RES_PATH_RE` 只认双引号，而 `ast.unparse()` 输出**单引号** | A 段 Python 侧恒返回「无」 |
| `_GD_ASSIGN_RE` 少 `re.M` | `^` 只匹配文件首行 → C 段恒返回「无」 |

另修两处**误报**：`@property` / `@x.setter` 不算「被遮蔽的方法」
（`_rt.RandomNumberGenerator.seed` 是**防遮蔽的正当写法**）；
排除 `enum` 块 + 接受 dict-key 形态（消掉 147 处枚举成员误报）。
